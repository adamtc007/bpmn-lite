## Correction (2026-07-22, during V5 scoping)

**0.11's "VERIFIED, minor caveat" verdict was too loose — the differential harness it verified is not the one V5.4/the V&S Depends-on line need, and this should have been a DEVIATION.** The probe confirmed *a* differential harness exists, runs from a CI-reachable entry point, and passes (15/15) — all true of `dmn-lite-engine/tests/differential_runner.rs`. But that harness compares the DMN decision-table VM against a reference evaluator; it is a different subsystem (`dmn-lite-*`, decision tables) from what "T9.7 differential-execution harness" means in this plan's own context — a BPMN workflow harness comparing DSL-authored and XML-authored lowerings of the same fixture for replay-hash equality (exactly what V5.4 specifies and what the V&S doc's own "Depends on" line names). No such BPMN harness exists, or ever did. The probe validated *presence of a differential-test pattern somewhere in the workspace*, not *presence of the specific harness the plan assumed as consumable substrate* — the caveat it did flag (a dead, unwired second replay binary) was real but beside the actual gap.

**Disposition:** not a crisis — V5.4 builds this harness from scratch, which was always going to be true regardless of when the gap was found; the DMN differential test remains a useful structural pattern to model it on. Recorded here, not silently absorbed into V5, because V0's entire purpose was catching assumed-substrate that doesn't exist before later tranches build on the assumption, and this is exactly that kind of miss — it just wasn't caught until V5.4 needed the substrate directly, three tranches later than it should have been. No other V0 row is implicated; this is specific to 0.11's differential-harness half (the replay-harness half of 0.11 was correctly verified and remains sound).

**Transferable lesson (Adam, 2026-07-22), worth generalizing beyond this one row:** the probe verified the harness *existed and ran*, never that it was the *right* one for the substrate claim being reconciled. "Runs from a CI entry point, passes" is satisfied by any differential harness in the workspace, including one from an entirely unrelated subsystem — existence is cheap to confirm and easy to mistake for the actual claim. A substrate-reconciliation probe must assert **identity**, not existence: not "does a thing matching this description exist and work," but "is *this specific* thing, doing *this specific* comparison, the one downstream tranches will actually depend on." If V0 is ever re-run, or a similar reconciliation pass is written for a future programme, this is the check to tighten first — it would have caught 0.11's gap on the first pass rather than the third.

**Second instance of the same error, one turn later (Adam, 2026-07-22, `EOP-PLAN-BPMN-ISA-002.md` item 5.2a):** a ruling that inclusive gateways had "zero live-manifest, zero test-fixture usage" was itself wrong — the search behind it never checked `bpmn-lite-engine/src/tests.rs`, which carries a full six-test specification of the feature. Caught by the full `cargo test --workspace` run, not by the narrower checks the ruling was based on. The lesson generalizes past 0.11: **a claim that a ruling turns on needs its own scope statement, not a bare conclusion.** "Zero usage" is unfalsifiable-sounding and reads as settled; "searched files X and Y for identifier Z" is checkable and invites "what about the other crate, or the raw tag text?" before the ruling ships rather than after. Both misses were evidence narrower than the claim it was asked to support — write the search down, not just its conclusion.
